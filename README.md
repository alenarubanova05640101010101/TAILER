# Тайлер — жизнь вне расписания

Приложение для студентов: находить мероприятия вуза и знакомиться с теми, кто идёт туда же, ещё до события. Идея — в [docs/IDEA.md](docs/IDEA.md), план — в [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md).

## Быстрый старт

Нужен Node.js ≥ 18. Зависимостей и сборки нет.

```bash
npm start          # http://localhost:8080 — приложение + локальный сервер синхронизации с календарями
npm run start:static   # только статика (python3), без синхронизации
npm test           # юнит-тесты логики, данных и сервера
```

## Синхронизация с Google и Apple календарём

Без настройки в карточке события работают кнопки «Google Календарь» (открывает готовую форму) и «Apple Календарь» (скачивает .ics). Чтобы события добавлялись сами, `npm start` поднимает локальный сервер ([server/](server/)), а в профиле появляется панель «Календари».

**Google.** Скопируй `.env.example` в `.env`. В [Google Cloud Console](https://console.cloud.google.com) включи Google Calendar API, создай OAuth client ID типа Web application с redirect URI `http://localhost:8080/api/google/callback`, добавь свой аккаунт в Test users и впиши `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`. Перезапусти сервер, в профиле нажми «Подключить».

**Apple (iCloud).** Создай пароль приложения на appleid.apple.com (Вход и безопасность → Пароли приложений) и введи его с Apple ID в профиле: «Apple Календарь» → «Подключить». Используется CalDAV, событие попадает в первый календарь iCloud.

Кнопка «Добавить мои события» отправляет в подключённые календари всё, на что ты записана. Повторная отправка обновляет те же события, дублей нет. Токены и пароль приложения лежат в `.data/accounts.json` (права 0600, папка в .gitignore) и никогда не отдаются в браузер. Сервер слушает только 127.0.0.1, проверяет Host и принимает изменяющие запросы только со своим заголовком. Синхронизируются события из афиши; события, созданные в кабинете организатора, остаются только в браузере.

Модули ES не открываются через `file://`, запускайте через сервер.

## Структура

- `dist/` — само приложение (HTML, CSS, ES-модули `model.js` — логика, `app.js` — интерфейс, `events.js` — данные событий, `img/` — обложки).
- `server/` — локальный сервер (Node без зависимостей): раздача `dist/`, Google OAuth, CalDAV для iCloud.
- `tests/` — тесты на `node:test`.
- `tools/` — скрипты обновления данных из публичных Telegram-каналов (Python 3 + curl).
- `docs/` — идея и план.

## Безопасность и данные

Профиль и чаты хранятся только в localStorage браузера. Локальный сервер нужен только для синхронизации календарей и ничего не отправляет никуда, кроме Google и iCloud. Весь пользовательский ввод экранируется при выводе, ссылки контактов принимаются только как `https://` или `@username`, в `index.html` задана Content-Security-Policy. Секретов в репозитории нет. Участники «Найди своих», сообщения и баллы вымышлены.

# Подробности прототипа

Адаптивный интерактивный прототип по IMPLEMENTATION_PLAN.md и видеореференсу.

Четыре основных экрана: «Для тебя», «Афиша», «Чаты», «Профиль». Подробности мероприятий, профиль, компания, уведомления и демопанель открываются в диалогах. Телефон: нижняя навигация. Десктоп: боковая панель.

## Ноябрьские события

Мероприятия лежат в [dist/events.js](dist/events.js): 18 событий на ноябрь 2026 из публичных Telegram-каналов студорганизаций НИУ ВШЭ, у каждого есть ссылка на исходный пост (`source`). Сферы — 14 интересов (спорт, волонтёрские организации, бизнес, стартапы, интернациональная Вышка, национальные, кино-, юмористические, музыкальные, творческие, развлекательные, разговорные, медиа- и языковые клубы) (`spheres`); события фильтруются и рекомендуются по ним.

Обновить данные: `python3 tools/fetch_posts.py 2026-10-25` скачает посты из `tools/channels.txt` (через `t.me/s/…`) в `tools/posts.json`; новые события добавляются в `events.js` вручную после проверки. Каналы без веб-превью (закрытые или с отключённым просмотром) скрипт не видит. VK-сообщества не подключены.

## Проверка

`npm test`

## Демонстрация

1. На главной принять персональное предложение дизайн-встречи.
2. В карточке включить открытость и открыть список участников.
3. Предложить Кате пойти вместе: приглашение появляется в «Чатах», в переписке с Катей, со статусом «Отправлено → Ответ получен → Идёте вместе».
4. В профиле открыть панель демо. Подтвердить принятие приглашения (ответ Кати придёт в чат, на вкладке «Чаты» появится значок), затем посещение обоими.
5. Проверить историю: 100 баллов за посещение и 30 за приглашение. Повторные подтверждения не начисляют баллы снова.
6. В панели демо можно восстановить исходные данные.

Время фиксировано: 25 октября 2026, 12:00 МСК. События реальные, но на 25 октября объявлены не все: многие клубы публикуют анонсы за 1–2 недели. Три участника «Найди своих» и счётчики баллов вымышлены. Реальные контакты, сообщения, вход в вуз, серверная база и синхронизация устройств не подключены. Данные хранятся в localStorage текущего браузера. Установка PWA и офлайн-кеш — отдельный этап; этот прототип работает по веб-ссылке.

## Валидация

Автоматические проверки бизнес-логики: однократное начисление, замена 50 на 100, порог баланса, отмена, отказ, приглашение и оба порядка посещения, сериализация и сортировка. Синтаксис JS проверен Node.js.

Встроенный preview в среде недоступен (отсутствует sites-previewd mailbox). Визуальная проверка в браузере и на физических iPhone/MacBook не выполнена.

## Регистрация

Сначала имя, фамилия и направление обучения (все обязательны), затем «Мои интересы» (нужно выбрать хотя бы один; первыми в списке идут Интернациональная Вышка, Бизнес и Стартапы), затем одно необязательное поле «Как с тобой связаться»: мессенджер, соцсеть или телефон в свободной форме (до 120 символов). Счётчик шагов не показывается. Пока интересы не выбраны, приложение остаётся на регистрации. Редактирование профиля требует то же самое. Тумблер «Показывать мой контакт» работает, если контакт указан. Профиль хранится в localStorage этого браузера; сервера, проверки личности и переноса между устройствами нет. Сброс демо возвращает к регистрации.

## Чаты

Вкладка «Чаты» (`#chats`): слева список переписок, справа выбранная. На телефоне список и переписка открываются по очереди. Приглашение «Предложить пойти вместе» (из «Найди своих» или кнопкой «Позвать на событие» в самом чате) уходит карточкой в переписку с этим человеком. В карточке виден статус по шагам и подпись, куда пришёл ответ. После отправки в «Найди своих» у человека появляется «Открыть чат». Можно писать и обычные сообщения. Непрочитанные считаются в значке на вкладке.

Баллы за приглашение (+30) по-прежнему только за Катю и только по правилам выше. Максиму и Алине приглашение уходит в их чат без баллов и без ответа: ответ в демо вызывается только за Катю (панель демо). Данные чатов лежат в том же снимке localStorage (`chats`), старые сохранения при загрузке получают карточку приглашения Кате (`withChats`). Реальной доставки нет: собеседники вымышлены, сообщения никуда не отправляются.

Логика чата — в [dist/model.js](dist/model.js) (`sendChatInvite`, `sendText`, `inviteStatus`, `markRead`, `threads`), тесты — в `tests/model.test.mjs`.

## Счётчик, календарь, напоминания

- **Счётчик на карточке и в событии:** «Идут N · M открыты к знакомству · K с твоими интересами». N и M — вымышленные участники события плюс ты, если записан и открыт; K — сколько из идущих делят хотя бы один интерес с твоим профилем (`crowd` в `model.js`). Состав участников у каждого события свой: пул из 30 вымышленных людей, ранжированный по пересечению интересов (размеры — таблица `CROWD`).
- **Мало открытых (меньше 3):** вместо пустоты блок «Ты будешь одним из первых — мы напомним, когда кто-то присоединится» и кнопка «Позвать друга». В демо такие события — «Экологический кейс», «Мой Дальний», «Я — профессионал», тренинги 10, 11, 14 и 21 ноября.
- **В календарь:** кнопка скачивает `.ics` (время по Москве; события без времени — на весь день) с будильником за час: «Через час X, 3 открытых участника идут». Число в файле фиксируется на момент скачивания.
- **Позвать друга:** Web Share API; если браузер его не поддерживает, текст и ссылка копируются в буфер.
- **«Мы напомним»** работает только внутри приложения: после «Я иду» в уведомлениях появляется напоминание, а новые открытые участники — в демопанели кнопкой «присоединился ещё один открытый участник». Системные push не подключены.

## Вход для организаторов

Отдельная ссылка: `/organizer.html` (из приложения участника на неё нет перехода). Вход демо: выбираешь свою организацию, пароля нет.

- **Обзор:** сколько записалось через Тайлер, сколько открыты к знакомству, сколько знакомств начато (приглашения в чатах), доля первокурсников, просмотры и конверсия «просмотр → запись»; по каждому событию — воронка и интересы идущих.
- **Мероприятия:** правка названия, описания, даты, места и т. д. у событий организации, добавление своих и удаление своих. Кнопка «Заполнить из текста поста» разбирает анонс правилами (дата, время, место), это не нейросеть: сети и ключа у приложения нет.
- **Каналы:** организатор создаёт канал и публикует сообщения (можно прикрепить мероприятие); участники находят их во вкладке «Каналы» и подписываются.

Данные организатора лежат в `localStorage` (`tyler-organizer-v1`), участник читает их оттуда же, поэтому на одном устройстве оба входа видят друг друга. Реальными в статистике являются только действия, сделанные в этом браузере; участники «Найди своих», просмотры и сохранения по базовым событиям — демо-оценка. Чтобы цифры собирались от настоящих студентов, нужен сервер (аккаунты, общая база, проверка организаторов).
